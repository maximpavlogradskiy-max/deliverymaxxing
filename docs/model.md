# Модель

## Постановка

Решения на каждый временной блок t (час или смена):

- `N_t` — число поваров, `M_t` — число курьеров (целые);
- `b_t` — ставка продвижения в Яндекс Еде (оплата за заказ; бюджет не ограничен).

Цель — дисконтированная прибыль, а не выручка и не загрузка поваров:

```
max  Σ_t δ^t · E[π_t],     π_t = Σ_каналы m_c · served_c − c_N·N_t − c_M·M_t − b_t · P_t(b_t)
```

- `m_c` — маржинальный доход заказа канала c: цена − фудкост − комиссия − курьер − упаковка;
- `P_t(b)` — число оплачиваемых промо-заказов при ставке b;
- `served` ограничен мощностью: `served ≤ min(D, K_кухня(N), K_курьеры(M))` — две очереди подряд.

Решения принимаются по маржинальным величинам, а не по средним.

## Кухня и зал делят мощность — теневая цена

Зал и доставка тратят один ресурс — повар-минуты. По двойственности LP у мощности кухни есть
теневая цена μ_t. Заказ доставки выгоден, если

```
m_доставка − μ_t · t_доставка > 0
```

где t — повар-минуты на заказ. Когда кухня не загружена до предела, μ_t = 0 и любой заказ
с положительной маржой выгоден: зарплата поваров уже заплачена. Ограничивать доставку в пик
имеет смысл, только если кухня упирается в мощность (μ > 0), маржа на повар-минуту у доставки
ниже, чем у зала, и в зале есть неудовлетворённый спрос.

## Мощность — это очередь, а не μ·N

Формула Кингмана для одного обслуживающего:

```
E[W] ≈ ρ/(1−ρ) · (C²ₐ + C²ₛ)/2 · E[S]
```

При ρ → 1 ожидание растёт гиперболически, поэтому эффективная мощность K задаётся вероятностным
ограничением `P(время > SLA) ≤ ε`, а не 100% загрузкой. Для нескольких обслуживающих —
правило квадратного корня: `N ≈ R + β√R`, R = λ/μ.

Закон Литтла `L = λ·W` связывает число гостей в зале, поток и длительность визита. При
фиксированном числе мест рост W из-за медленной кухни снижает поток гостей зала.

## Сколько мощности держать — задача газетчика

Если заказ сверх мощности теряется, оптимальная мощность K* удовлетворяет

```
P(D > K*) = c_u / m,     c_u — стоимость единицы мощности (смена / заказов за смену)
```

Спрос — счётные данные с избыточной дисперсией: отрицательное биномиальное, а не Пуассон.

## Повара и промо — комплементы

`∂²E[π]/∂N∂s = m · λ g'(s) · f_D(K) · K'(N) ≥ 0` — функция прибыли супермодулярна, и по
теореме Топкиса оптимальный уровень промо не убывает с числом поваров. Решать эти два вопроса
отдельно — ошибка.

## Промо с оплатой за заказ

- Расход = ставка × промо-заказы, поэтому он растёт вместе со спросом. Регрессия заказов на
  расход бессмысленна; управляемый рычаг — ставка.
- Безубыточность: `q · r · чек ≥ ставка`, где q — доля оплаченных промо-заказов, которые
  действительно дополнительные, r — маржинальность.
- Если ставка определяет цену всех промо-заказов, маржинальная стоимость дополнительного
  заказа равна `b + P(b)/P'(b) > b`.
- Долгосрочный эффект: новый клиент стоит `LTV = m·f·(1+d)/(1+d−r_ret)`, а не m. Оценка LTV
  очень чувствительна к удержанию r_ret вблизи 1.

## Идентификация эффекта промо

- Атрибуция агрегатора ≠ эффект: в «заказы от продвижения» входят клиенты, которые заказали бы
  и так.
- Естественный эксперимент со сменой ставки → оценка Вальда:
  `q ≈ Δ(всех заказов) / Δ(оплаченных промо-заказов)`.
- Свой эксперимент — чередование уровня ставки по дням (switchback). Дней на группу:
  `n = 2 (z_{1−α/2} + z_{1−β})² σ² / δ²`, σ² — остаточная дисперсия дневных заказов после
  учёта дня недели.
- Если бюджет меняли в ответ на провалы заказов, история смещена. Проверка — что чему
  предшествует (тест Грейнджера): `Δs_t = α + Σ β_k (y_{t−k} − ŷ_{t−k}) + ε_t`.
- Когда кухня на стопе, наблюдается `min(D, K)`, а не D — спрос цензурирован, и наивная
  модель занижает его именно в пиках.
